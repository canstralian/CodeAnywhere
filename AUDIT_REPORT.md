## Executive Summary

The codebase is well-structured with strong TypeScript discipline, good separation of concerns, and a solid testing foundation. Several security concerns and reliability gaps were identified and partially remediated in this audit. The most critical issue was the Mermaid diagram renderer running with `securityLevel: "loose"`, which permitted arbitrary JavaScript execution from AI-generated content.

## Findings & Remediations

### 1. CRITICAL — Mermaid XSS via `securityLevel: "loose"`

**File**: `webview-ui/src/components/common/MermaidBlock.tsx:39`
**Severity**: High
**Status**: **Fixed**

Mermaid was initialized with `securityLevel: "loose"`, which disables all script sanitization and allows arbitrary JavaScript execution within rendered diagrams. Since diagrams are generated by AI models and may be influenced by adversarial inputs (prompt injection), this represented a concrete XSS vector in the VSCode webview sandbox.

```diff
- securityLevel: "loose",
+ securityLevel: "antiscript",
```

`"antiscript"` permits HTML labels (preserving diagram quality) while stripping all `<script>` tags and JavaScript event handlers from rendered output.

---

### 2. MEDIUM — `innerHTML` assignment in `CopyButton.tsx`

**File**: `webview-ui/src/components/history/CopyButton.tsx:19-21`
**Severity**: Medium
**Status**: **Fixed**

Used `document.createElement("div")` + `innerHTML` to strip HTML tags from task text before copying. This pattern creates a transient DOM node with potentially malicious markup before extraction.

```diff
- const tempDiv = document.createElement("div")
- tempDiv.innerHTML = itemTask
- const text = tempDiv.textContent || tempDiv.innerText || ""
+ const doc = new DOMParser().parseFromString(itemTask, "text/html")
+ const text = doc.body.textContent || ""
```

`DOMParser` with `text/html` parses in a detached document context, preventing side effects like resource fetches triggered by `<img>`, `<script>`, or `<link>` tags.

### 3. MEDIUM — CI/CD Node.js Version Inconsistency

**File**: `.github/workflows/code-qa.yml`
**Severity**: Medium
**Status**: **Fixed**

The `check-translations` and `test-webview` jobs hardcoded `node-version: '18'` while the global `NODE_VERSION` env var was set to `20.18.1`. This caused builds to use different Node versions across jobs, potentially masking version-specific failures.

```diff
- node-version: '18'
+ node-version: ${{ env.NODE_VERSION }}
```

Applied to both `check-translations` and `test-webview` jobs.

---

### 4. MEDIUM — No Dependency Vulnerability Scanning in CI

**File**: `.github/workflows/code-qa.yml`
**Severity**: Medium
**Status**: **Fixed**

No `npm audit` step existed. A new `security-audit` job was added that runs `npm audit --audit-level=high` for both the extension and webview workspaces, failing the build if any high/critical CVEs are detected in dependencies.

## Remaining Findings (Not Auto-Fixed)

### 6. MEDIUM — JSON.parse Without try-catch (15+ Occurrences)

**Files**: `webview-ui/src/components/chat/ChatView.tsx`, `ChatRow.tsx`, `BrowserSessionRow.tsx`, and others
**Severity**: Medium
**Recommendation**: Wrap all `JSON.parse()` calls in try-catch blocks and validate the shape of parsed data using the existing Zod schemas. Unhandled parse errors crash React components and can produce confusing blank states.

### 7. MEDIUM — `dangerouslySetInnerHTML` with Shiki Output

**File**: `webview-ui/src/components/ui/markdown/CodeBlock.tsx:57`
**Severity**: Medium
**Recommendation**: Shiki's `codeToHtml` output is generally safe, but the error fallback path (line 48) returns the raw `value` string which may contain `<` and `>` characters. Add explicit HTML escaping in the error fallback path. Consider wrapping with `DOMPurify.sanitize()` if a sanitization library is added.

**File**: `src/services/browser/BrowserSession.ts`
**Severity**: Low
**Recommendation**: The 1-hour connection cache does not validate whether the cached connection is still alive before reuse. Add a lightweight ping/health-check before using a cached `chromeHostUrl`.

### 9. LOW — Tree-Sitter Analysis Not Cached

**Severity**: Low (Performance)
**Recommendation**: Implement caching for tree-sitter parse results per file with mtime-based invalidation. The existing TODO comment acknowledges this gap.

## Positive Findings

The following areas are well-implemented:

- **TypeScript strict mode** with `noImplicitAny`, `noImplicitReturns`, `noFallthroughCasesInSwitch` — strong type discipline throughout.
- **MCP singleton thread safety** — promise-based double-check locking in `McpServerManager.ts` prevents race conditions during initialization.
- **Checkpoint path protection** — `ShadowCheckpointService.ts` blocks checkpoints in `~`, Desktop, Documents, Downloads.
- **Event listener cleanup** — `ChatTextArea.tsx` and context providers correctly clean up listeners on unmount.
- **Translation CI validation** — missing locale keys are caught in CI before merge.
- **WeakRef usage** in `McpHub.ts` prevents circular reference memory leaks.
- **Comprehensive test architecture** — unit tests for both extension and webview, plus E2E integration tests.
- **Debounced Mermaid rendering** — prevents excessive re-renders on rapid input changes.
